# QSafe-PoAR-DigitalTwin

Reproducible simulation code for the manuscript **“Quantum-Safe Agentic Digital Twin Blockchain Framework for Predictive Urban Disaster Resilience in 6G-Enabled Smart Cities.”**

This repository implements a simulation-oriented research artifact for evaluating urban disaster resilience with digital-twin synchronization, federated recovery intelligence, recovery-aware validator selection, a BFT-style confirmation layer, post-quantum cryptography integration hooks, adversarial stress tests, controlled ablations, and statistical reporting.

## Scope

The repository deliberately separates two concepts that are easy to conflate:

1. **Security eligibility** determines whether a candidate node is authenticated, authorized, fresh, and protocol-compliant.
2. **Proof-of-Adaptive-Recovery (PoAR)** ranks only security-eligible nodes according to operational recovery suitability.

PoAR is therefore implemented here as a **recovery-aware validator-selection mechanism**, not as an independent replacement for consensus safety or Byzantine fault tolerance. Proposal, voting, quorum, commit, timeout, and view-change behavior are handled by the consensus simulator.

## Main pipeline

`data_pipeline.py`  
→ `simulation.py`

Reviewer-requested robustness experiments are handled by `attacks.py`, `baselines.py`, `experiments.py`, and `ablation_sensitivity.py`.

## Reproducibility

The main configuration is stored in `config.yaml`. It records:

- independent random seeds;
- scenario duration and update interval;
- number of zones, sensors, gateways, validator-capable nodes, and active validators;
- synthetic edge/communication ranges;
- recovery-agent hyperparameters;
- PoAR weights, normalization ranges, eligibility thresholds, freshness limits, and fallback rules;
- BFT quorum/fault assumptions;
- network latency, packet loss, and partition parameters;
- cryptographic mode and parameter-set labels;
- carbon-aware resilience index weights;
- adversarial attack intensities.

The public-data provenance specification is stored separately in `data_manifest.yaml`.

## One-command reproduction

```bash
python -m pip install -r requirements.txt
python reproduce.py
```

A faster smoke test is available with:

```bash
python reproduce.py --quick
```

The scripts generate run-level CSV files, scenario summaries, statistical comparisons, ablation results, and sensitivity results in a runtime `results/` directory. That directory is generated by the code and is intentionally not part of this flat source repository.

## Experiments

The experiment matrix contains the following scenario families:

- S1: intense rainfall flooding;
- S2: cyclone-influenced rainfall;
- S3: localized seismic disturbance;
- S4: road-network isolation;
- S5: edge-node energy depletion;
- S6: communication partitioning;
- S7: carbon-constrained emergency operation;
- S8: integrated compound disaster.

Each scenario is evaluated over independent seeds. Metrics are computed from run-level outputs rather than hard-coded manuscript values.

## Baselines

Implemented comparison policies include:

- centralized monitoring;
- digital-twin-only prediction;
- conventional blockchain validation;
- classical-security blockchain;
- centralized recovery learning;
- energy-unaware validator selection;
- carbon-unaware validator selection;
- static routing;
- round-robin validator selection;
- random eligible selection;
- resource-aware validator selection;
- PBFT-style fixed-membership confirmation.

The framework also supports controlled component ablations so that baseline comparison is not incorrectly treated as ablation.

## Adversarial tests

The attack module supports reproducible stress injection for:

- Byzantine validator behavior;
- spoofed sensor observations;
- replay/stale reports;
- model poisoning;
- denial-of-service / validator unavailability;
- packet loss and communication delay;
- asymmetric partitions;
- compromised digital-twin reports;
- manipulation of PoAR attributes.

Security claims should be limited to the attack models actually executed.

## Post-quantum cryptography

`pqc_security.py` supports two modes:

- `oqs`: use the `oqs` Python package when a compatible liboqs installation is available;
- `modeled`: deterministic, parameterized cryptographic overhead modeling for environments where liboqs is unavailable.

The modeled mode is **not** presented as a cryptographic implementation. It exists so that the full simulation remains executable while preserving an explicit distinction between protocol simulation and actual cryptographic execution.

## Statistical reporting

`evaluation.py` reports, where applicable:

- mean;
- standard deviation;
- 95% confidence interval;
- paired or independent statistical tests;
- exact p-values;
- effect sizes;
- Holm multiple-comparison correction;
- confusion-matrix-derived warning metrics.

Independent simulation runs are treated as the replication unit.

## Important research-use note

The manuscript currently reports specific aggregate values. This repository does not embed those values as constants. All results are recomputed from documented seeds, configurations, scenarios, and generated run-level outputs. Manuscript tables should be updated from the reproducible outputs produced by the finalized code and configuration.
